# NearSheets

A NEAR table interface using React, Univer, shadcn-style Radix controls, TanStack Query and local Dexie documents. The comprehensive refactor in [the brief](docs/nearsheets-refactor.md) is still in progress; visual acceptance remains pending. The user chose a browser-first application without a separate login backend.

The workbook starts blank. Use **Blockchain category dropdowns** to insert a formula at the active cell, edit its arguments, and use the result in other formulas. `NEAR_BALANCE` and `FT_BALANCE` return spreadsheet numbers; exact source units remain in read evidence. `NEAR_VIEW` returns scalars or a record/table range. `SPUTNIK_PROPOSALS` returns the first 100 proposals with stable contract IDs. Univer manages spills and reports collisions with occupied cells. Inspect the data to see freshness or query errors; refresh explicitly for current state.

`SPUTNIK_TRANSFER`, `SPUTNIK_VOTE`, `SPUTNIK_CALL`, `SPUTNIK_STAKE` and `INTENTS_SWAP` produce inspectable descriptors. Use decimal **strings** for exact payments. Token precision comes from `ft_metadata`; native NEAR always uses 24 decimals. `NS_FIELD` selects amount, baseUnits, recipient, asset, source, network or kind. `NS_STATUS` and `NS_RECEIPT` return execution evidence to cells. An action reference identifies the operation independently of coordinates. Copies retain that identity and recorded attempts block repeat submission; use a new reference only for a genuinely new operation.

Select action cells and choose **Blockchain → Review actions**. This explicit step may allocate Intents deposit instructions. The dialog shows the actual calls and freezes the reviewed snapshot/account/network. Attempt persistence must succeed before signing. Changed inputs, policy, metadata or proposal state require review again. Unknown outcomes block automatic retries; **Blockchain → Details** can reconcile a known hash. A submitted DAO proposal is awaiting governance, not a completed payment.

Intents uses the configured 1Click API, its runtime token catalog, safe `dry:true` estimates and explicit `dry:false` preparation. DAO funding currently supports NEAR fungible tokens and validated NEAR, EVM and Solana destinations. It does not support every provider chain, native-NEAR wrapping, testnet, confidential custody or partner credentials in the browser. `INTENTS_STATUS` reports the recorded deposit's provider stage, including settlement and refund. Expired routes require a new proposal; NearSheets refuses approval of its expired routes. Plain Sputnik transfers cannot enforce deadlines on chain, so another client can still approve an expired transfer.

**File → Open** lists existing local documents. JSON preserves the native workbook, plugin resources, descriptors, read evidence and execution history; import creates a new document and retains historical evidence. Legacy `trezu-sheets` v1/v2 envelopes migrate to v3, renaming function tokens outside quoted text. The IndexedDB database retains its legacy name so existing data stays accessible. JSON and CSV export capture current edits independently of storage writes. CSV is values-only; imports preserve leading zeros/large integer strings and force formula-like text to remain text. Other spreadsheet tools may interpret formula-like CSV text differently.

Wallet connection uses the pinned NEP-641-capable connector described in [the compatibility audit](docs/references/wallets.md#nearsheets-connector-compatibility-audit-2026-11-11). Wallet restoration and service sessions are separate. A credentialed auth client supports server challenges, ownership authorization, session restoration, expiry and logout, but it remains optional for a future named integration. No separate NearSheets backend or service-login UI is required for the current workflows. A URL alone does not verify a backend. Local editing and wallet operations remain available without service authentication. Optional providers can come from a compatible configured manifest.

Use Node 24 and pnpm. Required checks are `pnpm typecheck`, `pnpm build`, and focused Vitest files (`pnpm exec vitest run tests/table-runtime.test.ts`, for example). Agents must not start servers, browsers, screenshots, or production blockchain/service probes without explicit authorization. Visual validation of spills, focus restoration, keyboard editing, dialogs and narrow layouts is pending. Configuration uses T3 Env/Zod; `VITE_` values are public and secrets require a server boundary.

The header shows the document title, local save state, an Open shortcut and menus for less frequent commands. Univer’s original formatting toolbar, formula bar and sheet controls stay visible by default. The native ribbon tabs are Edit, Formulas, View and Blockchain. Selecting Blockchain replaces the ribbon contents with balance/proposal reads, transfer/vote/swap/staking/contract-call preparation, refresh/details and a review button showing the selected action count. These are native ribbon commands, with no additional NEAR strip. The native category dropdowns select a function, then a focused argument dialog generates the underlying expression; direct formula typing keeps Univer’s autocomplete and argument hints. No custom global keyboard shortcuts intercept sheet editing.

Ribbon tabs use a flat, left-aligned underline treatment. Category dropdowns use Solar Linear icons. Refresh, details and selection review sit on the right when space allows; Univer retains native overflow for narrow windows. Solar attribution is available in File → About NearSheets.

Blockchain functions are grouped into Accounts & tokens, DAO, Swaps, Contracts & staking, and Results dropdowns. Selecting an entry opens only its arguments, captured target cell and formula preview; there is no search sidebar or second function selection. Insert writes a formula, while execution remains a separate reviewed action.
