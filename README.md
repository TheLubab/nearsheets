# NearSheets

A browser-first NEAR spreadsheet built with React, Univer, Radix controls, TanStack Query and local Dexie documents. The core implementation exists; the comprehensive refactor is not yet signed off. See [implementation status](docs/implementation-status.md) for evidence, limitations and pending acceptance checks.

## Workbook and controls

Start with a blank workbook and organize arbitrary cells, ranges and sheets. **File remains in the ribbon tab row**, where the user placed it, alongside Home, Formulas, View and Blockchain. The document header shows the title, save state and wallet control. Univer's formatting ribbon, formula bar and sheet controls remain available. The ribbon tabs, toolbar and formula bar use white surfaces, with light gray row and column headers, subtle neutral gray grid lines, warm neutral controls and visible blue selection outlines. The title area, dialogs and other application surfaces use white, with reference colors retained for controls and accents. The logo and favicon share a Pear (`#CBD83B`) to Indigo (`#A88AED`) gradient with a Blue (`#4B63B6`) mark; new workbook templates retain the reference palette. Error states and wallet provider marks retain their semantic/brand colors. Saved workbook cell formatting remains user-owned. Solar Linear icons identify ribbon categories. The ribbon toolbar is 54px tall with added vertical and horizontal padding. Inner ribbon controls use consistent 34px heights, 20px command icons, 6px gaps, pill shapes, translucent white hover/pressed surfaces, medium-weight (500) dark charcoal labels and blue keyboard focus; dropdowns and split buttons share the treatment. Toolbar labels do not select on drag; editable inputs retain text selection. Full visual acceptance is pending.

The **Blockchain** tab contains **Balances**, **DAO proposals**, **Cross-chain swaps**, **Contracts & staking**, and **Action results** dropdowns. Choosing a function opens its argument dialog with a captured target cell and formula preview. Direct typing retains formula autocomplete and argument hints. Refresh, Details and Review actions are native ribbon commands; review shows the selected action count. Freeze and fullscreen commands are available from the sheet footer's context menu. No custom global shortcuts intercept editing.

After successful document startup, a welcome dialog offers **Getting started**, **Use a template** and **Start blank** until you close it or choose an option. Refreshing before that choice shows welcome again, even though startup has already saved a blank workbook. Existing workbooks remain available. Dismissal is a separate local preference; unavailable preference storage does not block editing.

**File → Getting started** creates a fresh editable tutorial with an offline cell-reference example, account balance instructions and an introduction to deliberate review/signing. **File → Templates…** offers Team payroll, Invoices & expenses, Community budget, International payouts, Treasury overview and Grants & rewards, alongside Portfolio & balances and Proposal review. Each opens on real read-only blockchain formulas with editable public mainnet accounts or quote routes. No illustrative Example sheets are inserted; action inputs stay blank until configured deliberately. The eight workflows include NEAR/USDT/USDC balances and portfolio allocation, payroll hours/rates, invoice due dates, category budgets, milestone grants, staking proposals, voting and three-scenario Intents quote comparison. Planning amounts remain approximate; exact approved payment amounts are entered separately. See [workbook design and limits](docs/template-workbooks.md). Each creates an independent local workbook with fresh IDs; existing copies are never updated from the catalog. Creation saves existing edits before switching and keeps the current document open on failure. Payment templates require a Sputnik shared treasury, unique reference, recipient and Amount input. Decimal inputs preserve their digits internally; full-precision balance details are available through Inspect. Signing submits proposals for treasury approval, not completed payments; notes and dates do not schedule transfers. International payouts use supported mainnet NEAR fungible-token funding and provider-supported destinations; calculation only requests dry estimates, and review explicitly prepares deposit instructions. No wallet is required to create or edit a template. Welcome/picker keyboard behavior and workbook visual acceptance remain pending.

Document/editor startup and longer calculations use scoped, delayed toasts. Calculation feedback follows pending network queries: “Fetching blockchain data…” for RPC reads, “Fetching swap quotes…” for Intents work, and “Calculating…” for local processing. It retains Stop; fast and cached reads stay quiet. Persistent errors remain in their relevant control or dialog. Application notifications use the wrapper in `src/components/ui/toast.ts` so they do not duplicate inside Univer's toaster.

## Data, balances and precision

[The formula catalog](docs/functions.md) records all current blockchain signatures and the additional local helper functions.

`NEAR_BALANCE` and `FT_BALANCE` return approximate spreadsheet numbers for ordinary calculations. Direct balance formulas receive thousands separators, up to six fractional digits and no trailing zeros. Positive values below `0.000001` display as `<0.000001`; zero displays as `0`. The cell does not append a token symbol: put the unit in a heading or adjacent column. Balance cells also use shrink-to-fit: when the formatted number is wider than the column, the text shrinks so every digit stays visible instead of becoming `######` or scientific notation. Widen the column if you prefer a larger, uniform font. Formatting does not round the underlying numeric value, but conversion from an exact on-chain amount to a JavaScript number can already have lost precision.

Choosing Number, General, Percentage or another toolbar format replaces the automatic format. Manual choices survive save/reopen through the native balance-format resource. Old workbooks without that resource preserve existing explicit formats. Calculated cells such as `=A1/2` use normal spreadsheet formatting.

`NEAR_BALANCE_EXACT(account, network)` and `FT_BALANCE_EXACT(token, account, network)` return exact decimal **text**. Reference those cells in transaction amount arguments to retain every source digit. Converting the text to numbers or applying ordinary spreadsheet arithmetic can lose precision. Token decimals come from verified metadata; supported precision is 0–24, with NEAR fixed at 24. Explicit decimal strings with excess precision are rejected. Numeric calculations may have floating-point noise normalized by the amount parser; they do not have arbitrary precision.

Balances are the RPC-reported account amount or token-contract balance, not a guarantee that the entire amount is spendable. Native balances include funds needed for storage; fees and proposal bonds also matter. Details shows up to 30 selected populated cells, their formulas and underlying values first. Workbook read details separately expose exact balances, token identity, timestamps and raw data; reads are not automatically filtered to the selected cell.

`NEAR_VIEW` returns a scalar or record/table range. `SPUTNIK_PROPOSALS` reads the first 100 proposals from index zero. Univer handles spills and collisions; leave empty cells for returned tables. Quote tables occupy three columns and show exact decimal text, token symbols, asset/chain identity, expiry, slippage and original base units. Refresh clears the workbook runtime's cached queries and drafts and requests recalculation; calculation never signs or submits.

Failed blockchain formulas return real spreadsheet errors: invalid inputs use `#VALUE!`, confirmed missing accounts/contracts use `#N/A`, connection failures use `#CONNECT!`, and other failed reads use `#ERROR!`. Selecting the failed cell enriches Univer's native error popup with its cause and next step. Inspect shows the selected cell's explanation and expandable technical details. Dependent formulas propagate errors and `IFERROR` can handle them; a failed balance is never replaced with zero. Diagnostics are tied to the current cell/formula and recalculation, and are rebuilt rather than restored as current failures from saved workbooks. Ordinary downstream formulas keep Univer's standard error explanation.

## Review and execution

`SPUTNIK_TRANSFER`, `SPUTNIK_VOTE`, `SPUTNIK_CALL`, `SPUTNIK_STAKE` and `INTENTS_SWAP` return readable labels backed by workbook-runtime operation descriptors. `NS_FIELD` exposes an action's fields; `NS_STATUS` and `NS_RECEIPT` return recorded execution information. An action's identity is network + DAO + explicit reference, independent of its coordinates. Duplicate identities in a selection are rejected; copied submitted actions retain the recorded attempt protections.

Select action cells and choose **Blockchain → Review actions**. This explicit step can allocate Intents deposit instructions before opening the exact execution preview. **Sign reviewed actions** opens the wallet flow. Review requires a connected wallet on the same network and permission established by the current DAO policy. The preview shows the source, signer, recipient, exact amount/base units, gas, deposit and actual calls. Changed workbook/account/network, policy, token precision or proposal state requires a new review. Attempts must be persisted before invoking the wallet. Indeterminate outcomes block blind retries; Details can reconcile an available transaction hash. Without a hash, wallet/explorer verification is still required.

Argument dialogs validate literal account IDs, JSON, decimal amounts and slippage before insertion; cell references are validated during calculation. Review/reconciliation failures show a cause and recovery guidance. Cancelled, failed and uncertain wallet attempts are explained with their execution record; technical wallet details are retained separately. Non-confirmed signing outcomes also open an explanation after the wallet flow.

Submission creates a DAO proposal or casts a vote; it does not by itself establish completed payment or staking. `NS_STATUS` distinguishes confirmed proposal submission from vote confirmation. It does not automatically track every subsequent governance execution. Multiple selected actions generate separate wallet requests and are not atomic.

## Intents and wallet scope

The public 1Click-compatible API defaults to `https://1click.chaindefuser.com`; set `VITE_INTENTS_API_URL` to another endpoint or to `none` to disable it. It supplies the runtime asset catalog, `dry:true` estimates and explicit `dry:false` preparation. DAO funding currently supports mainnet NEAR fungible tokens with validated NEAR, EVM or Solana destinations. Unknown assets, chains without a validator, incompatible precision and expired quotes fail explicitly. There is no Intents testnet route, automatic native-NEAR wrapping, confidential custody or browser-held partner secret.

Expired submitted routes require a new reference and proposal. NearSheets includes expiry in its proposal description and refuses approval of its expired routes. Plain Sputnik transfers cannot enforce that deadline against other clients. `INTENTS_STATUS` reads the recorded deposit's provider state, including settlement, incomplete deposit and refund, separately from governance status. End-to-end live execution has not been established by the current mocked tests.

The **Sign In** control offers NEAR wallets and a separate Trezu Wallet option using the pinned NEP-641-capable NEAR Connect fork in [the compatibility audit](docs/references/wallets.md#nearsheets-connector-compatibility-audit-2026-11-11). Trezu is available on Mainnet only according to the captured manifest; its actual availability depends on the configured manifest and provider. The known Ledger, EVM, WalletConnect and passkey manifest entries are excluded from the selector in this version. Current local documents, RPC reads and wallet transactions require no separate NearSheets login/backend; connecting a wallet does not create a backend session. Optional cookie-session auth has a tested client boundary; when `VITE_AUTH_API_URL` is supplied, the provider attempts session restoration. There is no service-login UI or deployed NearSheets auth server established by this repository. Custom manifests or injected wallets can still provide other entries.

## Documents and interchange

**File → Open** lists local documents. JSON exports the v3 `nearsheets` envelope with the native workbook, plugin resources and execution journal. Legacy v1/v2 `trezu-sheets` documents migrate function tokens outside quoted text. The legacy IndexedDB database name is retained for compatibility. Import creates a new document instead of overwriting the source, and retains historical execution evidence. Export captures current edits independently of successful IndexedDB writes.

**File → Print…** opens a print view of the active sheet and the browser print dialog, including Save as PDF where supported. It uses current calculated/displayed values without refreshing or saving, omits hidden rows/columns, and retains merges, relative column widths and basic text/color formatting. The used content fits the page width; paper, orientation and scale are browser settings. This is a table printout: rich-text runs, drawings, exact row heights, custom fonts and advanced cell styling are not reproduced. Empty sheets and ranges over 100,000 cells report an error. Allow pop-ups if the browser blocks the print view.

Saved runtime read/draft resources are retained in JSON, but the current session initialization only restores the execution journal into the runtime. Drafts and read details are rebuilt by recalculation; offline restoration of those resources is a remaining gap. Balance-format ownership is restored by its own native resource hook.

**Download CSV (underlying values)** exports only the current sheet's cached values. It drops formulas, formatting, other sheets and execution metadata. Exported decimals can differ from the rounded grid display. Import preserves leading-zero integers and unsafe integer strings, forces leading `=` text to stay text, and converts other recognized numeric values to JavaScript numbers. CSV is not an exact-decimal workbook format; use native JSON for workbook fidelity. XLSX and remote document storage are deferred.

## Development and documentation

Use Node 24 and pnpm. Run `pnpm typecheck`, `pnpm build`, and meaningful focused tests, for example:

```sh
pnpm test tests/balance-format.test.ts tests/table-runtime.test.ts tests/table-selection.test.ts tests/intents-route.test.ts tests/blockchain-ribbon.test.ts
```

Configuration is validated centrally in `src/config/env.ts`; `.env.example` lists supported public values. Missing optional integrations disable only their respective features, except the public Intents provider, which defaults to `https://1click.chaindefuser.com`; set `VITE_INTENTS_API_URL=none` to disable it. Malformed supplied values fail clearly. All `VITE_` values are public. A custom RPC override applies only to the configured network. `VITE_TREZU_API_URL` reserves an integration endpoint; no enrichment adapter has been selected. Secrets require an authorized server boundary. This repository does not require a separate service-auth deployment for the current browser-first workflow.

Agents must follow [AGENTS.md](AGENTS.md): do not start servers, browsers, screenshots or live blockchain probes without the required explicit authorization. The last implementation checks passed; automated checks do not establish visual or live-chain acceptance.
