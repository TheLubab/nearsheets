## Verification record

The toolbar surface is 54px tall with 8px vertical and 16px horizontal padding, matched in the hidden overflow measurement container. The inner ribbon control revision (2026-11-12) styles ordinary commands, dropdowns and split buttons with 34px heights, pill shapes, 20px command icons and 14px medium-weight (500) labels, translucent white hover/active surfaces, contrasting text, darker muted disabled states (5.80:1 against the toolbar) and blue keyboard focus. Commands use 6px icon/label and inter-control gaps, 8px horizontal control padding and 10px group padding; dropdown chevrons remain 14px. Active controls have an inset border. Toolbar button/selector labels disable text selection; editable selector inputs remain selectable. Group separators and spacing also apply to Univer 1.4’s hidden measurement copy so overflow calculations use the same control dimensions. Typecheck, production build and all 3 Blockchain ribbon tests passed; existing browser externalization (`util`) and chunk-size warnings remain. Calculated color-pair contrast is 12.01:1 for ordinary text and 4.24:1 for the focus outline against the toolbar; these checks do not establish rendered UI acceptance. User inspection of Home formatting toggles, font/size inputs, color split buttons, other tabs and narrow-width overflow remains pending.

The connected-wallet panel displays the wallet's manifest logo, including after session restoration, with a generic icon if the logo is missing or fails to load. Visual confirmation remains pending.

The sheet-list dropdown trigger is hidden; its menu also exposed hidden sheets, so restoring a hidden sheet through that menu is unavailable.

The active ribbon tab masks the rounded toolbar border beneath it. The tab list permits visible overflow to avoid clipping the mask; narrow-screen tab access needs visual verification.

The white surface revision (2026-11-12) removes the ivory application background and yellow-tinted account surface; visual acceptance remains pending.

The white ribbon and formula bar revision (2026-11-12) retains neutral borders and selection indicators. Visual acceptance remains pending.

## Acceptance still outstanding

- Exercise one continuous blank-workbook workflow: read → calculate → exact draft → review → wallet result → save/reopen → receipt reconciliation. Existing focused tests do not establish the entire browser flow.
- Verify keyboard editing, autocomplete, formula spills/collisions, clipboard, sheet/row moves, multi-range selection, undo/redo, dialog focus and narrow layouts in the actual UI.
- Validate real wallet/deployed Sputnik compatibility through a separately authorized controlled testnet workflow. Intents has no testnet route; live mainnet verification requires separate explicit authorization.
- Restore saved read/draft runtime resources without relying on a new network recalculation, and verify offline reopening and exact source evidence retention.
- Complete the governance/provider lifecycle acceptance scenarios, including delayed approvals, expiry, settlement and refund. Current generic status functions do not automatically derive every downstream DAO execution state.
- Review remaining brief requirements against the implementation before milestone sign-off. General contract calls, tested helper utilities or a passing build do not establish every route as supported.

XLSX, remote document storage and a separate app-login backend are deferred or outside the selected current workflow. Unsupported Intents routes and unresolved token-weighted permission checks are implementation limits, not completed capabilities. This page records current status; it does not replace or reduce the milestone's acceptance requirements.
