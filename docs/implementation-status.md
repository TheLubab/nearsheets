## Verification record

Vercel Web Analytics (`@vercel/analytics` 2.0.1) is mounted once at the React root in `src/app/main.tsx`. Page views are reported automatically only when the build is served by Vercel; elsewhere the script request is unavailable and the app behaves normally. `VITE_VERCEL_ANALYTICS_MODE` selects `auto` (default), `production`, `development` or `none`. No bookkeeping persists locally for analytics. Ten env tests, typecheck and build passed; tracker delivery requires a Vercel deployment and remains unverified here.

File → Print… now prints the active sheet through a separate browser print view using current display values, merges, visible rows/columns, relative column widths and basic text/color styling. Printing does not save, refresh, sign or execute. Empty/oversized sheets and blocked pop-ups report errors; the view remains available after cancellation. Four focused tests, typecheck and build passed; build retains the existing browser-externalization and chunk-size warnings. Tests use the real Univer sheet/number-format plugins and mocked browser printing. This table renderer does not reproduce rich-text runs, drawings, exact row heights, custom fonts or advanced styling. Browser pagination, PDF output, cancellation/reprint and File-menu focus still require user inspection; no browser or server was launched.

Portfolio & balances now compares live NEAR, USDT and USDC across public Ref Finance exchange, Intents settlement and Ref Finance treasury accounts. Both token contracts are editable and precision remains RPC-verified. Each token has its own total and labels fall back to generic token names when contracts change. Forty-six template tests, typecheck and build passed; new assertions cover separate stablecoin totals and metadata requests. Actual rendered layout still needs user inspection.

Template amount UX now uses plain Amount labels and removes duplicate full-precision balance columns/rows from portfolio, funding and treasury sheets. Full source precision remains in Inspect; payment text formatting and exact conversion are preserved. Planning notes require deliberate rounding before entering a calculated payment amount. Forty-five template tests, typecheck and build passed. Existing saved workbooks are preserved; these layout changes apply to newly created templates. Visual acceptance is pending.

Loading feedback now follows the workbook query cache and distinguishes fetching blockchain data, fetching Intents quotes and local calculation. The same delayed notification ID and Stop action remain; cached results do not claim a new fetch. Five focused feedback tests, typecheck and build passed. User inspection of the notification transitions remains pending.

Dry Intents responses may omit quote.deadline. Parsing now accepts that shape, preserves the raw response, and exposes the sent deadline separately as a labeled requested estimate cutoff. Prepared funding routes without a provider deadline are rejected. Fifty-six focused tests, typecheck and build passed, including dry responses without deadlines and strict prepared-route expiry. Browser/live acceptance remains user-driven.

Intents requests now explicitly include a fresh ISO-8601 deadline ten minutes ahead for both dry estimates and explicit preparation. This addresses the observed public API HTTP 400 for a missing deadline; the pinned quickstart includes the field, though the captured reference table calls it optional. Returned provider expiry remains authoritative, and calculation stays dry. A strict request mock rejects missing/invalid/past deadlines; 54 focused Intents/template tests, typecheck and build passed. Live quote acceptance remains unverified in this agent session.

The Intents client now invokes the default browser fetch through globalThis instead of calling an unbound native function as a client method. This avoids receiver/Illegal-invocation failures before network dispatch. Transport diagnostics preserve method, URL and underlying exception, and cell popups show bounded technical details. Twenty-two focused Intents/error tests, typecheck and build passed; a receiver-sensitive mock covers the regression. No browser or live quote verification was performed.

The selected-cell error adapter now opens a native cell-alert fallback when Univer has no formula alert, rather than only enriching an existing popup. It subscribes to selection, calculation and edit visibility; clears on correction/disposal; and preserves a native formula alert when available. Thirteen focused error/selection tests, typecheck and build passed. Actual browser visibility remains pending user confirmation.

Referenced blockchain failures now enrich the native popup and Inspect for matching errors across cell/sheet references. Tracing is bounded and ignores successful results and changed source formulas. The exact cross-sheet quote comparison pattern is covered through the real formula engine and a mocked alert service. Typecheck, build and 12 focused error/selection tests passed. Browser popup appearance remains pending user confirmation.

## Acceptance still outstanding

- Exercise one continuous blank-workbook workflow: read → calculate → exact draft → review → wallet result → save/reopen → receipt reconciliation. Existing focused tests do not establish the entire browser flow.
- Verify keyboard editing, autocomplete, formula spills/collisions, clipboard, sheet/row moves, multi-range selection, undo/redo, dialog focus and narrow layouts in the actual UI.
- Validate real wallet/deployed Sputnik compatibility through a separately authorized controlled testnet workflow. Intents has no testnet route; live mainnet verification requires separate explicit authorization.
- Restore saved read/draft runtime resources without relying on a new network recalculation, and verify offline reopening and exact source evidence retention.
- Complete the governance/provider lifecycle acceptance scenarios, including delayed approvals, expiry, settlement and refund. Current generic status functions do not automatically derive every downstream DAO execution state.
- Review remaining brief requirements against the implementation before milestone sign-off. General contract calls, tested helper utilities or a passing build do not establish every route as supported.

XLSX, remote document storage and a separate app-login backend are deferred or outside the selected current workflow. Unsupported Intents routes and unresolved token-weighted permission checks are implementation limits, not completed capabilities. This page records current status; it does not replace or reduce the milestone's acceptance requirements.
